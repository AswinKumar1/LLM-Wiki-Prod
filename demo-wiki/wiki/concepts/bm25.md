# BM25 Algorithm

BM25 (Best Match 25) is a probabilistic ranking function used in information retrieval. It is the backbone of many production search systems including Elasticsearch, Apache Solr, and Lucene.

In `llm-wiki-universal`, BM25 powers `wiki search` — enabling instant keyword search over all wiki pages with **zero dependencies and zero API calls**.

## The formula

For a query Q with terms `q1, q2, ...` and a document D:

```
score(D, Q) = Σ IDF(qi) × [ f(qi, D) × (k1 + 1) ] / [ f(qi, D) + k1 × (1 - b + b × |D| / avgdl) ]
```

Where:
- `f(qi, D)` = term frequency of `qi` in document `D`
- `|D|` = document length in tokens
- `avgdl` = average document length across all documents
- `k1` = term frequency saturation parameter (typically 1.2–2.0)
- `b` = length normalisation parameter (typically 0.75)
- `IDF(qi)` = inverse document frequency of `qi`

## Why not just use embeddings?

Embedding-based search ([[vector-database]]) is better for semantic similarity ("find documents about dogs" also retrieves documents about "canines"). BM25 is better for:

- **Exact term matching** — searching for a specific function name, acronym, or proper noun
- **Speed** — BM25 builds in milliseconds; embeddings require GPU inference
- **No dependencies** — BM25 runs in pure Python; embeddings need sentence-transformers or an API
- **Explainability** — BM25 scores are interpretable; embedding distances are opaque

## Implementation in this project

`utils/search.py` implements BM25 Okapi entirely in Python stdlib:

1. Tokenise all wiki pages (lowercase, strip punctuation, remove stop words)
2. Build an in-memory term frequency index
3. At search time: score all documents and return top-k ranked by BM25 score
4. Extract a snippet showing where the match appeared

The index rebuilds on every search call — fast enough for wikis up to ~5,000 pages.
